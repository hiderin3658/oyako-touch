# 新種目「かたはめ（katahame）」 実装計画

## 目的
既存のタップ3択とは異なる **ドラッグ＆ドロップ（型はめ）** の新カテゴリ `katahame`（表示名「かたはめ」）を追加する。画面上部の「穴（形の輪郭・中抜き）」に、下部の「ピース（塗り図形）」から正しい形をドラッグして入れる。第1弾テーマは既存 `ShapeFigure` の5形（circle/triangle/square/star/heart）を流用し、**新規アセットは作らない**。正誤・星・完了・音声・ごほうび導線は既存の `QuizEngine` / `quizReducer` / `progress` / reward をそのまま再利用し、種目固有部分（穴＋複数ピースの共有ドラッグ）だけを新レンダラー `ShapeFitBoard` に閉じ込める。ノーフェイル思想（誤りは「もういちど」でやさしく戻す）を踏襲する。

## 確定した設計判断
1. ピース型は専用 `KatahameChoice` を定義（既存 `SizeChoice` 等の流儀に合わせる）。
2. 穴は `ShapeFigure` に後方互換 prop `variant="fill"|"outline"` を追加して中抜き表示（既存呼び出しは無指定＝従来の塗り）。
3. **タップ設置フォールバックを常時有効**（ドラッグに加え「ピースのタップ＝穴へ設置試行」）。3歳児のアクセシビリティ＋jsdom での決定論テストのため。
4. katahame は `problems.balance.test.ts` の `balancedCategories`（4:4:4・最大3択・正解index均等）には**追加しない**。代わりに「5形すべてが target に登場」する網羅チェックを追加。
5. ホームに新アクセント色を1つ追加（例 `--mint`）＋絵文字 🧩。
6. スナップ半径は穴半径×1.3程度、ピースは横並び固定配置（実機 M1 で微調整前提）。

## データモデル

### 型定義（`lib/types.ts`）
- `Category` に `"katahame"` を追加（6→7種目）。
- ピース型:
  ```ts
  /** かたはめのピース（塗り図形）。1問内は全ピース同色（形だけで判別させる） */
  export interface KatahameChoice extends ChoiceBase {
    shape: ShapeKind;
    color: string;
  }
  ```
- `Choice` ユニオンに `KatahameChoice` を追加。
- `Problem` 判別ユニオンに katahame 分岐を追加（穴の形は `target` で明示、`type: "shape-fit"`）:
  ```ts
  | {
      id: string;
      category: "katahame";
      type: "shape-fit";
      prompt: PromptData;
      target: ShapeKind;         // 穴の形。正解ピースの shape と一致
      choices: KatahameChoice[]; // ピース2〜3個（正解1＋ダミー1〜2）
      reward?: string;
    }
  ```

### 問題JSON（`content/problems/katahame.json`）
既存 `shape.json`/`size.json` と同一書式に `target` を足すだけ。音声は `prompt.audio` で共有。

生成側（`audio` 無し＝MP3を生成する代表）:
```json
{
  "id": "katahame-004", "category": "katahame", "type": "shape-fit",
  "prompt": { "text": "ほしを はめてね", "say": "ほしを はめてね" },
  "target": "star",
  "choices": [
    { "id": "p1", "label": "ほし",   "shape": "star",   "color": "#FFC92E", "correct": true },
    { "id": "p2", "label": "まる",   "shape": "circle", "color": "#FFC92E", "correct": false },
    { "id": "p3", "label": "しかく", "shape": "square", "color": "#FFC92E", "correct": false }
  ],
  "reward": "sticker-star"
}
```
再利用側（`audio` で同ターゲットの生成側を参照）:
```json
{
  "id": "katahame-009", "category": "katahame", "type": "shape-fit",
  "prompt": { "text": "ほしを はめてね", "say": "ほしを はめてね", "audio": "katahame-004" },

  "choices": [ /* 全ピース同色・正解は star */ ],

```
**ルール**：1問内の全ピースは同一 `color`（色ヒント排除）／`target` は正解ピースの `shape` と一致／ダミー shape は `target` と異なる。

## QuizEngine への統合（最小変更・ボードレンダラー方式）
現状は `choices.map(choice => <ChoiceComponent/>)` の per-choice 描画。型はめは穴＋複数ピースを共有ドラッグ状態でまとめて描画するため、**ボードレンダラー登録簿**を新設し「ボードがあれば委譲、無ければ従来描画」に分岐する。

`components/quiz/renderers/index.ts`:
```ts
type TapCategory = Exclude<Category, "katahame">;
export const choiceRenderers: Record<TapCategory, ChoiceRenderer> = { color, shape, number, animal, size, count };

export type BoardRenderer = (props: {
  problem: Problem; locked: boolean;
  onPlace: (choiceId: string, correct: boolean) => void;
}) => JSX.Element;
export const boardRenderers: Partial<Record<Category, BoardRenderer>> = { katahame: ShapeFitBoard };

export function isTapCategory(category: Category): category is TapCategory {
  return category !== "katahame";
}
```
- `choiceRenderers` を `Record<TapCategory>` 化することで、`Category` 拡張時もタップ6種の網羅性を保ちつつ katahame を型で除外。

`QuizEngine.tsx`（描画部のみ差し替え。`data-locked` ラッパは維持）:
```tsx
const BoardComponent = boardRenderers[lesson.category];
<div className={styles.choices} data-locked={state.status !== "playing"}>
  {BoardComponent ? (
    <BoardComponent key={currentProblem.id} problem={currentProblem}
      locked={state.status !== "playing"} onPlace={handleSelect} />
  ) : (
    isTapCategory(lesson.category) && choices.map((choice) => { /* 従来どおり */ })
  )}
</div>
```
- ボードは成功/誤り時に既存 `handleSelect(pieceId, correct)` を呼ぶだけ。星・「せいかい！/もういちど！」・sfx・ほめ言葉・`advance`・`retryAck`・音声途切れ防止・ロックはすべて既存ロジックを共有。
- `key={currentProblem.id}` で、次問（id変化）時のみ盤面が再マウントされ位置リセット。retry（同一id）では盤面保持。

## 新レンダラー `ShapeFitBoard`

### 純粋幾何（`components/quiz/renderers/shapeFit.ts`・DOM非依存）
```ts
export interface Point { x: number; y: number; }
export function distance(a: Point, b: Point): number;
export function isWithinSnap(pieceCenter: Point, holeCenter: Point, snapRadius: number): boolean; // 距離<=半径
export type DropResult = "fit" | "miss" | "return";
// 圏外→"return"（形一致でも戻す）／圏内かつ形一致→"fit"／圏内だが形不一致→"miss"
export function evaluateDrop(params: {
  pieceShape: ShapeKind; targetShape: ShapeKind;
  pieceCenter: Point; holeCenter: Point; snapRadius: number;
}): DropResult;
```

### レンダラー（`components/quiz/renderers/ShapeFitBoard.tsx`）
- props `{ problem, locked, onPlace }`。`problem` を katahame バリアントへ型ガードで絞り込む。
- 上部に穴（`ShapeFigure variant="outline"`、`target` 形、`data-testid="hole"`/`data-shape`）。下部トレイにピース群（`ShapeFigure` 塗り、`data-testid="piece"`/`data-shape`/`data-correct`）。
- **Pointer Events**（`pointerdown`/`pointermove`/`pointerup`）でタッチ・マウス両対応。掴む→`transform: translate()` 追従→離す時 `evaluateDrop` で判定。
  - `"fit"` → 穴中心へ吸着させ `onPlace(id,true)`。
  - `"miss"` → 元位置へやさしく戻し `onPlace(id,false)`（もういちど）。
  - `"return"` → 元位置へ戻すのみ（`onPlace` 呼ばない＝無反応・ノーフェイル）。
- **タップ設置フォールバック**：`pointerup` 時の総移動量が閾値未満（＝実質タップ）なら穴中心で `evaluateDrop`。ドラッグできない子でも遊べ、単体テストは `pointerDown`→`pointerUp`（無移動）で決定論発火。
- `locked` 中は全操作無視（二重発火防止）。
- **SSR/jsdom 安全**：`setPointerCapture`/`releasePointerCapture`/`getBoundingClientRect` は存在チェック。矩形取得不可でもタップ設置フォールバックで成立し例外を投げない。
- スナップ半径は穴半径×1.3程度。`prefers-reduced-motion` 時にアニメ無効でも判定・ノーフェイルは成立。

### `ShapeFigure` の穴対応（`components/quiz/renderers/ShapeChoice.tsx`）
`ShapeFigure` に後方互換 prop `variant`（既定 `"fill"`）を追加。`"outline"` は `fill="none"`＋`stroke`／太め `stroke-width`／`stroke-dasharray` で差し込み口に見せる。既存の `circle`/`rect`/`path` 要素構造は不変（`renderers.test.tsx` 維持）。
