# 新種目「なぞり（nazori）」 実装計画

## 目的
タップ3択・かたはめ（ドラッグ）に続く **第3のインタラクション「指でなぞる（trace）」** の新カテゴリ `nazori`（表示名「なぞり」）を追加する。大きな形の**破線ガイド（道）**をなぞり、道上の**通過点を順に消化**して大部分をたどると完成。完成で「なぞった線が色づく＋キラキラ＋『せいかい！』＋ほし」。**誤答の概念が無い**（完成まで続けられる＝ノーフェイルの純度が最も高い）。第1弾は既存 `ShapeFigure` の5形（circle/triangle/square/star/heart）を流用し**新規アセット不要**。正誤・星・完了・音声・ごほうびは既存 `QuizEngine`/`quizReducer`/`progress`/reward を再利用し、種目固有部分だけを新レンダラー `TraceBoard` と純粋関数 `traceProgress` に閉じ込める。**かたはめの `ShapeFitBoard` を雛形**とする。

## 確定した設計判断
1. `nazori` は**選択肢を持たない**。`Problem` の nazori 分岐は `target: ShapeKind` のみ・`type: "trace"`・`choices` なし。
2. `validateLesson` の**基底チェック（choices 2件以上・正解ちょうど1）を `category !== "nazori"` でガード**し、nazori は `target` のみ検証（既存6種目＋katahame は不変）。
3. 完成判定は**通過点方式**（純粋関数 `traceProgress`）。「消化率 ≥ 0.85 かつ 終点付近（残り ≤ lookahead）」で完成。
4. 道は `ShapeFigure variant="outline"`（かたはめで追加済み）が描く `circle`/`rect`/`path` を container ref → `querySelector` で参照し `getTotalLength()`/`getPointAtLength()` でサンプリング（**ShapeFigure 改変不要**）。
5. **jsdom は `getTotalLength`/`getPointAtLength` 非対応** → 存在チェック＋フォールバック（サンプル不能環境では pointerdown→pointerup の1セッションで完成）。例外を出さない。
6. 完成通知は `onPlace("trace", true)` の**正解経路のみ**（誤答経路は使わない）。星・せいかい・音声・advance・ロック・音声途切れ防止は既存共有。
7. ホームに新アクセント色 `--peach` を1つ追加＋絵文字 ✏️。8タイルは3列グリッドで 3+3+2。
8. `tolerance`/`lookahead`/`completeRatio`/サンプル点数は設定値として外出し（実機 NM2 で微調整前提）。完成時キラキラは既存 `Sparkles` を流用。

## データモデル

### 型（`lib/types.ts`）
- `Category` に `"nazori"` 追加（7→8）。新 Choice 型は不要（`Choice` ユニオン不変）。
- `Problem` に nazori 分岐（choices なし）:
  ```ts
  | {
      id: string;
      category: "nazori";
      type: "trace";
      prompt: PromptData;
      target: ShapeKind; // なぞる形（道の形）
      reward?: string;
    }
  ```

### 問題JSON（`content/problems/nazori.json`）
`choices` を持たず `target` のみ。音声は `prompt.audio` で共有。
```json
{ "id": "nazori-001", "category": "nazori", "type": "trace",
  "prompt": { "text": "まるを なぞってね", "say": "まるを なぞってね" },
  "target": "circle", "reward": "sticker-circle" }
```
再利用側：`"prompt": { …, "say": "まるを なぞってね", "audio": "nazori-001" }`。ルール：`target` は有効 ShapeKind／`choices` は持たない（あれば空配列）／`say` は参照先と一致。

## validateLesson の nazori 分岐（`lib/problems.ts`）
基底の choices/correct チェック2ブロックを `if (category !== "nazori") { … }` でガード（**唯一の基底改変**・既存は不変）。加えて nazori 専用検証：
```ts
if (category === "nazori") {
  const target = problem.target;
  if (typeof target !== "string" || !VALID_SHAPES.includes(target)) {
    throw new Error(`problem(${problem.id}) の target が不正な形です: ${String(target)}`);
  }
  if (problem.choices !== undefined &&
      (!Array.isArray(problem.choices) || problem.choices.length !== 0)) {
    throw new Error(`problem(${problem.id}) の nazori は choices を持ちません`);
  }
}
```
`lessonSources` に `nazori: nazoriData` 追記（`Record<Category>` なので漏れはコンパイルエラー）。

## QuizEngine 統合（`components/quiz/QuizEngine.tsx`）
盤面レンダラー方式は整備済み。`boardRenderers.nazori` に登録するだけで委譲経路に乗る。**唯一の変更**は choices の安全アクセス（choices を持たない nazori が判別ユニオンに増えるため）:
```ts
const choices: Choice[] = "choices" in currentProblem ? currentProblem.choices : [];
```
ボードは完成時 `onPlace("trace", true)` を1回呼ぶだけ。星・「せいかい！」・sfx・ほめ言葉・`advance`・`data-locked`・音声途切れ防止・`key={currentProblem.id}` リマウントは既存共有。誤答経路は発生しない。

## 新レンダラー `TraceBoard` と純粋関数 `traceProgress`

### 純粋判定（`components/quiz/renderers/traceProgress.ts`・DOM非依存）
`Point`/`distance` は `./shapeFit` から再利用（DRY）。
```ts
export interface TraceState { nextIndex: number; consumed: number; }
export interface TraceConfig { tolerance: number; lookahead: number; completeRatio: number; }
export function initialTraceState(): TraceState;
// points[nextIndex..+lookahead] のうち finger 許容半径内にある最も先まで frontier 前進（順消化・逆行しない）
export function advanceTrace(state: TraceState, points: readonly Point[], finger: Point, config: TraceConfig): TraceState;
export function traceRatio(state: TraceState, points: readonly Point[]): number; // nextIndex/length
// 消化率 >= completeRatio かつ 終点付近（残り <= lookahead）
export function isTraceComplete(state: TraceState, points: readonly Point[], config: TraceConfig): boolean;
```
frontier（contiguous prefix）モデル。`lookahead` で「順にたどりつつ少し飛ばしてよい」を表現。座標系は viewBox `0 0 100 100` のユーザー座標に統一（解像度非依存）。

### レンダラー（`components/quiz/renderers/TraceBoard.tsx`）
props は `BoardRenderer` と同一 `{ problem, locked, onPlace }`。`problem.category !== "nazori"` を型ガード。
- **描画（2レイヤー）**：道ガイド（`ShapeFigure variant="outline"` 中立色・破線）＋進捗オーバーレイ（同形 outline を絶対配置で重ね、`querySelector` で幾何要素を掴み `strokeDasharray=L`/`strokeDashoffset=L*(1-traceRatio)`）＝なぞった分だけ色づく。スタート目印（`data-testid="trace-start"`）。ルートに `data-testid="trace-board"`。
- **道サンプリング（layout effect）**：幾何要素を `querySelector("circle, rect, path")` で取得。`getTotalLength`/`getPointAtLength` の存在確認後、N点（例16）を等間隔サンプル（ユーザー座標0..100）。
- **指座標マッピング**：Pointer の clientX/Y を、ガイド SVG の `getBoundingClientRect()` と viewBox スケール100で同じユーザー座標へ写像（`fx=(clientX-rect.left)/rect.width*100`）。jsdom 安全。
- **Pointer Events**：down/move/up/cancel。`setPointerCapture`/`releasePointerCapture` は存在チェック。`touch-action: none`。move ごとに `advanceTrace` を適用し state 更新。`isTraceComplete` になった瞬間に一度だけ `onPlace("trace", true)`（`completedRef` で二重発火防止）＋全色化＋`Sparkles`。外れても何も起きない。未完成で指を離しても状態保持で再開可（ノーフェイル）。
- **フォールバック**：サンプル不能（`getPointAtLength` 不在/例外）なら pointerdown→pointerup の1セッションで完成成立（jsdom 決定論化）。実機はサンプル可能なので**単なるタップでは完成せず**実際になぞる必要あり。
- **locked 中**は全操作無視。`prefers-reduced-motion` で色づき無効でも判定・完成は成立。

## リスクと対策
- validateLesson 基底ガードのデグレ → `!== "nazori"` の一点のみ。既存 `problems.*.test.ts`／`problems.katahame.test.ts` が回帰ゲート。
- QuizEngine choices 型エラー → 安全アクセス化（board 経路では未使用）。
- 型網羅ゲート → progress/lessonSources の nazori 追記漏れはコンパイルエラー。
- 音声整合ゲート → nazori-001〜005.mp3 コミット必須。
- jsdom 非対応 → 存在チェック＋フォールバック、純粋判定は `traceProgress.test.ts` で網羅。
- E2E 決定論 → `page.evaluate` で幾何のサンプル点を client 座標化し実ドラッグでなぞる。許容半径が過小だとフレークするため NM2 で調整。
- タッチのスクロール競合 → `touch-action: none`。
- home 8タイル → 3列グリッド 3+3+2 目視。
- 進捗後方互換 → `normalizeProgress` が nazori 補完。
