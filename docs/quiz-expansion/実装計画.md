# 実装計画: すうじ 1〜10 化 ＋ 新種目「おおきさ」「かず」追加 ＋ 全6種目 正解位置 4:4:4 化

## 概要 / 目的

3歳児向け学習アプリの「選択肢バリエーション不足」と「正解位置の偏り」を解消する。承認済み計画（`~/.claude/plans/shimmering-yawning-platypus.md`）を実装レベルまで具体化したデータ設計書。

1. **すうじ改修**: 数字を 1〜5 → **1〜10** に拡張し、正解位置を 4:4:4 に。
2. **おおきさ（size）**: 同一図形の大中小 3 択から「いちばん おおきい／ちいさい」を選ぶ新種目。SVG 再利用で画像生成不要。
3. **かず（count）**: お皿＋果物 n 個の完成画像 3 択から「いちばん おおい／すくない」を選ぶ新種目。HiggsField で画像生成。
4. **全6種目 正解位置 4:4:4 化**: シャッフルは導入せず、**各 JSON の `correct:true` の並び位置（choices index 0=左/1=中/2=右）** で各位置4問ずつに配置する。

> 前提（調査済み確定事項）: 選択肢はどのレイヤーでもシャッフルされない。`pickProblems` は出題順のみシャッフル、`QuizEngine` は `choices.map` で JSON 記載順に描画する。よって正解位置は JSON の並び順で決まる。全種目 12 問プール・1 レッスン 5 問ランダム抽出（`SESSION_QUESTION_COUNT=5`）・全種目 3 択。

## 主要インターフェース

### 型（`lib/types.ts`）
```ts
export type Category = "color" | "shape" | "number" | "animal" | "size" | "count";

/** おおきさの選択肢（同一図形をサイズ違いで描画） */
export interface SizeChoice extends ChoiceBase {
  shape: ShapeKind;                       // circle | square | triangle | star | heart
  color: string;
  size: "large" | "medium" | "small";
}

/** かずの選択肢（お皿＋果物 n 個の完成画像） */
export interface CountChoice extends ChoiceBase {
  image: string;                          // /images/plates/{fruit}-{count}.png
  fruit: string;                          // strawberry|orange|apple|grape|banana（メタ・検証用）
  count: number;                          // 1〜5（メタ・検証用）
}

export type Choice =
  | ColorChoice | ShapeChoice | NumberChoice | AnimalChoice | SizeChoice | CountChoice;

// Problem 判別ユニオンに以下 2 分岐を追加
//  | { id; category:"size";  type:"select-one"; prompt; choices: SizeChoice[];  reward? }
//  | { id; category:"count"; type:"select-one"; prompt; choices: CountChoice[]; reward? }
```

### 検証（`lib/problems.ts`／`validateLesson`）
- `lesson.category` の許可リストに `"size"` `"count"` を追加。
- `category === "size"`: 各 choice の `size` が `"large" | "medium" | "small"` のいずれかであること。
  - メッセージ例: `problem(${id}) の choice には size(large|medium|small) が必要です`
- `category === "count"`: 各 choice の `image` が非空 string、かつ `count` が number であること。
  - メッセージ例: `problem(${id}) の choice には非空の image が必要です` / `… number 型の count が必要です`

### レンダラ共通シグネチャ（既存踏襲）
```ts
(props: { choice: Choice; state: "idle"|"right"|"wrong"; onSelect: () => void }) => JSX.Element
```
- 既存 5 レンダラ同様、`<button aria-label={choice.label} data-testid="choice" data-correct data-state onClick>` 構造を厳守（e2e/テストのセレクタ互換のため）。

### SizeChoice レンダラ設計
- `ShapeChoice.tsx` の `ShapeFigure` に `export` を付けて import（推奨・最小変更）。
- `ShapeFigure` を size に応じたラッパ box で囲みスケールする（拡大率 large=1.0 / medium=0.66 / small=0.45）。
```tsx
const scaleClass = { large: styles.sizeLarge, medium: styles.sizeMedium, small: styles.sizeSmall }[size];
return (
  <button type="button" className={buildClassName(state)} onClick={onSelect}
    aria-label={choice.label} data-state={state} data-testid="choice"
    data-correct={choice.correct ? "true" : "false"}>
    <span className={`${styles.sizeWrap} ${scaleClass}`}>
      <ShapeFigure shape={shape} color={color} />
    </span>
  </button>
);
```
CSS（`Choice.module.css` 追加）:
```css
.sizeWrap { display:flex; align-items:center; justify-content:center; width:100%; height:100%; }
.sizeLarge  { width:100%; height:100%; }
.sizeMedium { width:66%;  height:66%;  }
.sizeSmall  { width:45%;  height:45%;  }
```

### CountChoice レンダラ設計

## データの流れ / 依存関係

`content/problems/*.json`（ビルド時 import）→ `lessonSources`（problems.ts）→ `loadLesson`＋`validateLesson` → `pickProblems`（出題順のみシャッフル・5問抽出）→ `GamePage` → `QuizEngine` → `choiceRenderers[category]` でレンダラ委譲 → クリアで `recordLessonClear`/`addSticker`（progress.ts, localStorage）。正解位置は **JSON の choices 並び順のみ**で決まる（本計画の 4:4:4 化の唯一のレバー）。

## 影響範囲・考慮事項

- **後方互換（進捗）**: 既存 localStorage に size/count キーが無くても `normalizeProgress` が初期値補完（破壊しない）。ただし補完対象にするには**ループ配列への追記が必須**（型で守られない）。
- **home レイアウト**: タイルが 4 → **6 個**に増える。6 個は幅次第で 3×2 / 2×3 に折り返す。**縦がはみ出さないか実機確認（手動 M）**。
- **エラーハンドリング方針**: `validateLesson` は既存同様に Error を throw（握りつぶさない）。
- **音声**: 新設問は未生成でも Web Speech フォールバックで読み上げ。後日 `gen:audio:gemini:prod` で MP3 生成すれば自動差し替え。
- **新規ライブラリ**: **不要**。SVG は既存 `ShapeFigure` 流用、画像生成は HiggsField MCP（npm 依存ではない）。

## (C) count 種目（新規 `category:"count"`・表示名「かず」）

- お皿＋果物 n 個の**完成画像 1 枚**を 3 択。果物 5 種: strawberry(いちご)/orange(みかん)/apple(りんご)/grape(ぶどう)/banana(バナナ)、個数 1〜5。
- 設問「いちばん おおいのは どれ？」「いちばん すくないのは どれ？」を **6:6** 混在。
- **同一問題内は 3 択とも果物が異なり、個数もすべて異なる**。正解 = おおい設問なら最多個数、すくない設問なら最少個数。
- 各 choice: `{ image, fruit, count, correct }`。ラベル = 「<果物> <個数語>」（個数語 1=ひとつ/2=ふたつ/3=みっつ/4=よっつ/5=いつつ）。
- `type:"select-one"`、`reward:"sticker-count"`、`image = /images/plates/{fruit}-{count}.png`。
