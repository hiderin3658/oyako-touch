# 出題音声の再利用（オプトイン共有） 実装計画

## 目的

**音声ファイルは基本、問題ごとに 1 つある**という前提は維持する。
そのうえで、「読み上げが同じで音声を使い回したい」問題については、
**その問題に指定を足すだけで既存の音声ファイルを再利用できる**ようにする。

- デフォルト挙動は現状のまま（`/audio/q/<問題ID>.mp3`）で **変更なし**
- 再利用は**オプトイン**（指定した問題だけが共有する）

## 実データ（本実装で適用した削減）

| カテゴリ | 問題数 | ユニーク読み上げ | 生成音声 | 再利用 |
|----------|:---:|:---:|:---:|:---:|
| animal | 12 | 12 | 12 | 0（据え置き） |
| color | 12 | 8 | 12 | 0（今回スコープ外） |
| shape | 12 | 6 | 12 | 0（今回スコープ外） |
| **count** | 12 | 2 | **2** | 10 |
| **size** | 12 | 2 | **2** | 10 |
| **number** | 12 | 10 | **10** | 2 |
| **合計** | 72 | — | **50** | 22 |

- 出題音声は **72 → 50 ファイル**（22 個削減）。
- 今回の適用スコープは合意どおり **count / size / number**。color(8) / shape(6) にも重複はあるが据え置き（将来同方式で削減可能）。

> 注: 当初レポートの「44」はセッション中の読み込み不整合による誤集計だった。実データの読点区切り `say`（例「ろく、は どれかな」）等を反映した正しい値は **50**。

## 方針

`PromptData`（設問の読み上げ定義）に既にある任意フィールド `audio` を使う。

```ts
// lib/types.ts（既存・変更不要）
export interface PromptData {
  text: string;
  say: string;
  audio?: string; // 再利用する音声ファイルの語幹（省略時は問題 ID）
}
```

- `audio` 未指定 → 従来どおり `problem.id` の音声を使う／生成する
- `audio` 指定あり → その語幹の音声を使う（別の問題の音声を再利用）／その問題自身の音声は生成しない

### データ例（size：本来 2 種でよいケース）

```jsonc
{ "id": "size-001", "prompt": { "text": "…", "say": "いちばん おおきいのは どれ" } }
{ "id": "size-002", "prompt": { "text": "…", "say": "いちばん ちいさいのは どれ" } }
{ "id": "size-003", "prompt": { "text": "…", "say": "いちばん おおきいのは どれ", "audio": "size-001" } }
{ "id": "size-004", "prompt": { "text": "…", "say": "いちばん ちいさいのは どれ", "audio": "size-002" } }
```

- `size-003` は再生時 `/audio/q/size-001.mp3` を鳴らす。生成される音声は size-001 / size-002 の 2 つだけ。
- `say` は再生失敗時の Web Speech フォールバック文言として意味を持つため、`audio` を足しても残す。

## 再生側の変更（実装済み）

`components/quiz/QuizEngine.tsx`。音声名を導出する 1 行を追加し、参照する 2 箇所（自動読み上げ・マスコットタップ）で使う。

```ts
const currentProblemId = currentProblem.id;
// audio 指定があれば既存音声を再利用、無ければ問題 ID の音声（従来どおり）
const currentAudioName = currentProblem.prompt.audio ?? currentProblemId;
// …
playClip(`/audio/q/${currentAudioName}.mp3`, currentSay); // 自動読み上げ／再読み上げの両方
```

## 生成スクリプトの変更（実装済み）

`scripts/gen-audio.mjs` と `scripts/gen-audio-gemini.mjs` の `collectQuestionTargets`：

```js
for (const problem of lesson.problems ?? []) {
  // audio 指定がある問題は既存音声を再利用するため生成しない（参照先が別途生成される）
  if (problem.prompt?.audio) continue;
  const text = problem.prompt?.say ?? problem.prompt?.text;
  // …従来どおり ${problem.id}.mp3 を生成
}
```

- `audio` 付き問題は TTS 呼び出し・ファイル生成をスキップ。
- 参照先（`audio` の値 = 別問題の ID）は、その問題自身が `audio` 未指定なので通常どおり生成される。

## 音声資産の整理（実装済み）

- count-003〜012（10）／ size-003〜012（10）／ number-011, number-012（2）
- 削除後 `public/audio/q` は 50 ファイル。

## リスクと対策

| リスク | 対策 |
|--------|------|
| `audio` の参照先ミスで 404 | 整合テスト（参照先存在・生成対象一致）＋再生側 Web Speech フォールバック |
| 参照先の読みと不一致（誤読） | 整合テストで `say` 一致を検証 |
| 旧音声の消し忘れ | 孤立 MP3 検出テストで検知 |

## スコープ外

- `phrases.json`（固定句）・`sfx.json`（効果音）: 既に意味キーで共有済み
- color / shape の重複削減（将来同方式で対応可能）
