# 3歳児向け タブレット学習Webアプリ 設計書

作成日: 2026-06-27 / バージョン: 0.2（ドラフト）
変更点(0.2): Google認証＋DB不使用の許可リスト、親ログイン→子画面の遷移、すりあわせ用プロトタイプと段階的拡張フローを追加。

---

## 1. 目的・コンセプト

スマイルゼミ／こどもちゃれんじのような月額制タブレット教材を、自前のWebアプリで置き換える。
3歳児（年少相当）が **一人で・タブレットに直接触れて** 進められることを最優先とする。

- 月額課金なし（自分でホスティング・コンテンツ生成）
- タブレット1台で完結（紙・玩具なし）
- まず動くMVPを最短で立ち上げ、種目・問題数を段階的に追加

---

## 2. 対象ユーザーと非機能要件（3歳児UXの大原則）

設計の良し悪しは「内容」より先に「操作の作法」で決まる。以下は必須要件として全画面で守る。

| 原則 | 具体要件 |
|---|---|
| **全問読み上げ前提** | 字が読めない前提。問題文・選択肢・正解・励ましまですべて音声（ElevenLabs事前生成）。画面に頼らせない。 |
| **タップ＆ドラッグのみ** | タップ領域は最低64px、推奨80px以上＋周囲に余白。ドラッグは「正解の近くで吸着」。フリック・長押し・ピンチは使わない。 |
| **ノーフェイル設計** | 「×」「ふせいかい」を出さない。間違えても「もういちど！」とやさしく再挑戦。失敗で先に進めなくなる仕掛けを作らない。 |
| **即時フィードバック＋ごほうび** | 正解で音・キラキラ・マスコットの反応。1レッスン終了でシール／メダル等のコレクション要素（継続率の生命線）。 |
| **短時間・変化のある反復** | 1レッスン5問・3〜5分。1日10〜15分。同じ問題型で対象物や配置だけ変え、毎回違って見せる。 |
| **誤操作防止** | 端や「設定」へ子どもが誤って飛ばない。画面の向きは固定（横向き推奨）。 |
| **保護者エリア分離** | ログイン・進捗確認・ログアウトは「長押し＋ゲート」等、子どもが入れない場所に隔離。 |

## 3. 技術スタック

| 領域 | 採用 | 備考 |
|---|---|---|
| フレームワーク | Next.js（App Router）+ TypeScript | 既存資産（Vercel運用）と一致 |
| ホスティング | Vercel | CDN配信、`public/`静的配信を活用 |
| **認証** | **Auth.js (NextAuth v5) + Google Provider** | DBアダプタなし・JWTセッション。許可リスト方式 |
| **データ保存** | **DBなし**（静的JSON + `public/`） | 問題＝JSONマニフェスト、画像/音声＝`public/`、進捗＝localStorage |
| 画像生成 | **Higgsfield + Nano Banana Pro** | 必要箇所のみ。透過PNG・統一画風で事前生成 |
| 音声生成 | **ElevenLabs**（事前生成MP3） | リアルタイム不要なので品質重視モデルでOK |
| アニメ/演出 | CSS / Framer Motion 等 | 正解時のキラキラ、吸着、マスコットの動き |

> **DBを使わない方針**：問題は固定セットなので静的JSONで十分。画像・音声は事前生成して`public/`に置きCDN配信。進捗・メダルは1台完結の家庭用途のため`localStorage`。ユーザー管理も「許可リスト」で済むためユーザーテーブル不要（§4）。将来、複数端末同期やコンテンツ大量追加が必要になった時点で、Supabase Storage＋メタデータへ移行を検討する。

## 4. 認証・アクセス制御（Google認証 / DB不使用の許可リスト）

利用者がごく少数のため、ユーザーDBは持たず、**許可リスト（allowlist）に載せたメールアドレスだけ**がログインできる方式とする。

### 4.1 構成
- **Auth.js (NextAuth v5)** に **Google Provider** を設定。
- **DBアダプタは使わない**（`session.strategy = "jwt"`）。ユーザー情報は永続化しない。
- 許可リストは **DBではなく環境変数または静的設定ファイル** で管理。
  - 例: 環境変数 `ALLOWED_EMAILS="parent1@gmail.com,parent2@gmail.com"`
  - または `/config/allowlist.ts`（リポジトリ管理。Git管理したくなければ env を採用）
- `signIn` コールバックで、ログインしたGoogleアカウントのメールが許可リストに含まれるか判定。**含まれなければログイン拒否**。

```ts
// auth.ts （概念コード）
import NextAuth from "next-auth";
import Google from "next-auth/providers/google";

const ALLOWED = (process.env.ALLOWED_EMAILS ?? "").split(",").map(s => s.trim().toLowerCase());

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [Google],
  session: { strategy: "jwt" },   // DB不使用
  callbacks: {
    async signIn({ profile }) {
      const email = profile?.email?.toLowerCase();
      return !!email && ALLOWED.includes(email);  // 許可リスト外は false=拒否
    },
  },
});
```

> アドレスの追加＝環境変数（Vercelの Project → Settings → Environment Variables）に1行足して再デプロイするだけ。「あまり使う人がいない」用途に最小コストで合致。

### 4.2 親ログイン → 子画面の切替フロー
1. 未ログインでアクセス → **保護者向けログイン画面**（「保護者の方がログインしてください」＋「Googleでログイン」ボタン）。
2. Google認証成功＋許可リスト通過 → セッション確立。
3. セッションありの状態で **子ども向けホーム画面** を表示（＝ログイン成功で自動的に子画面へ切替）。
4. 子ども画面には**ログアウト・設定を子どもが押せる位置に置かない**。保護者メニュー（ログアウト含む）は「ロックアイコンの長押し」等のゲートの奥に隔離。
5. ミドルウェア（`middleware.ts`）で保護: 未ログインは子ページに入れずログイン画面へリダイレクト。

> セッションが生きている間は、次回以降アプリを開くと**ログイン画面を飛ばして直接子画面**に入れる（毎回親が認証する手間を避ける）。ログアウトは保護者メニューからのみ。

## 5. 機能仕様（問題種目）

調査済みのスマイルゼミ年少10分野を、**画像が要る／CSS・SVGだけで作れる**で仕分け。MVPは画像ゼロで作れる種目から着手する。

| 種目 | 内容 | 操作 | 画像 | フェーズ |
|---|---|---|---|---|
| いろあわせ | 「あかいのは どれ？」色つき図形から選ぶ | タップ選択 | 不要（CSS） | P1 |
| かたちはめ | まる・さんかく・しかくを選ぶ／型はめ | タップ/ドラッグ | 不要（SVG） | P1 |
| かずをかぞえよう | 同じ絵をN個並べて数える／「3このりんご」を選ぶ | タップ | **要** | P3 |
| おおい・すくない | 数の多い少ないを比較 | タップ | 流用 | P3 |
| なかまあつめ | どうぶつ／たべもの／のりものをカゴへ振り分け | ドラッグ | **要** | P3 |
| おとさがし | 「『あ』からはじまるのは？」絵を選ぶ | タップ | **要** | P4 |
| ひらがなタッチ | 「『あ』はどれ？」文字認識（なぞり書きは運筆判定が必要なので後回し） | タップ | 文字はフォント可 | P4 |
| えあわせ（神経衰弱） | 絵カードのペア合わせ | タップ | **要（ペア）** | P4 |

**MVPスコープ（P1）= いろあわせ＋かたちはめ**。画像ゼロ・外部API不要で「動いてデプロイできる」状態を最短で作る。

### 問題データモデル（JSON例）

```json
{
  "id": "color-001",
  "category": "color",
  "type": "select-one",
  "prompt": { "text": "あかいのは どれかな？", "audio": "audio/q/color-001.mp3" },
  "choices": [
    { "id": "c1", "label": "あか", "color": "#E53935", "correct": true },
    { "id": "c2", "label": "あお", "color": "#1E88E5", "correct": false },
    { "id": "c3", "label": "きいろ", "color": "#FDD835", "correct": false }
  ],
  "feedback": { "correct": "audio/fb/correct-01.mp3", "retry": "audio/fb/retry-01.mp3" },
  "reward": "sticker-apple"
}
```

画像を使う種目（数・仲間分け）は`choices`や`object`が画像アセットを参照する。

```json
{
  "id": "count-003", "category": "count", "type": "tap-count",
  "prompt": { "text": "りんごは いくつ あるかな？", "audio": "audio/q/count-003.mp3" },
  "object": { "image": "images/items/apple.png", "count": 3 },
  "answer": 3, "choices": [2, 3, 4]
}
```

## 6. ディレクトリ構成（案）

```

/middleware.ts               ← 未ログイン保護

/app/(kid)/...               ← 子ども向け画面（要セッション）
/app/(parent)/...            ← 保護者エリア（ゲート付き・ログアウト）
/lib/progress.ts             ← localStorage進捗管理
```

## 7. 画像アセット設計（Higgsfield + Nano Banana Pro）

### 7.1 方針
- **色・形は生成しない**（CSS/SVG/絵文字で足りる）。生成するのは「数えるモノ」「仲間分けのモノ」「音さがし・絵合わせのモノ」「マスコット」だけ。
- 全アセットを **背景透過PNG・1:1・統一画風** で生成し、`/public/images/`へ配置。
- 「全体的に可愛らしいタッチ」を担保するため、**共通スタイルブロックを全プロンプト先頭に固定**し、被写体だけ差し替える。

### 7.2 共通スタイルブロック（全プロンプト先頭に付与）

```
Cute, friendly children's flat illustration for a Japanese preschool learning app.
Soft rounded shapes, thick smooth outlines, cheerful pastel and primary colors,
gentle soft shading, kawaii style, big and clear, instantly recognizable for a 3-year-old.
A single subject centered in frame. Pure transparent background (PNG, no background).
No text, no numbers, no logo, no border, no drop shadow.
Keep the exact same art style, line weight, and color palette across every image.
Aspect ratio 1:1.
Subject: 〈ここに被写体を記述〉
```

## 8. 音声設計（ElevenLabs）

### 8.1 推奨ボイス（3歳児の女の子向け・日本語ナレーション）

「明るく・はっきり・やさしい」声を、**アプリ全体で1ボイスに統一**するのを基本とする。

| 候補 | 特徴 | 用途 |
|---|---|---|
| **Akari（Bright & Natural Japanese Female）** ★第一候補 | クリア・フレンドリー・表情豊か | 読み上げ＋励まし |
| **Sakura（Calm and gentle）** | 自然で穏やか・発音クリア | 落ち着いた代替 |
| **Shizuka（Natural & Soft）** | クリアでやさしい | 同上の代替 |
| Yui / Hina（cute系） | 可愛い・キャラ寄り | 掛け声だけ別ボイスにしたい場合 |

> コミュニティ音声。本番文言で試聴し `voice_id` を控える。クレジット消費・商用利用条件を確認。

### 8.2 モデルと推奨設定
- **モデル：Eleven Multilingual v2**（日本語プロソディが自然。事前生成なので低遅延不要）。大量バッチは Turbo v2.5、最大表現力は Eleven v3 も選択肢。
- **設定の目安**：Stability 0.45–0.6 / Similarity 0.75 / Style 0–0.3 / **Speed≈0.9（ゆっくり）**。

### 8.3 生成・配置フロー（DB不使用と整合）
固定セットなので**ビルド前に全文言を一括生成→`public/audio/`へMP3書き出し**。実行時API呼び出しなし。
1. 問題JSONの `prompt.text` ＋固定フィードバック文言を集約
2. `scripts/gen-audio.ts` が `id` ごとにMP3生成 → `public/audio/q|fb/<id>.mp3`（既存はスキップの差分生成）
3. アプリは `<audio>` で再生（自動再生＋マスコットタップで再生）

> `ELEVENLABS_API_KEY` は生成スクリプト専用（クライアント非露出）。本番ランタイムはMP3配信のみでキー不要。

## 9. 画面と遷移

```
[ログイン]（保護者）── Googleでログイン → 許可リスト判定
   │  成功
   ▼
[おうち]（子ども）── カテゴリ選択（大きなアイコン＋マスコット）
   │
   ├─[レッスン] 5問 → 各問: 音声自動再生 → タップ/ドラッグ → 即時フィードバック（ノーフェイル）
   │
   └─[ごほうび] シール/メダル獲得アニメ → コレクション帳

[保護者メニュー]（ロック長押しゲート）── ログアウト / 進捗・取り組み記録
```

- 既存セッションがあれば次回からログイン画面はスキップし直接[おうち]へ。
- レッスン中は戻る/設定を子どもの手の届く所に置かない。画面の向きは固定。

## 10. 進捗・ごほうび（localStorage）
- `localStorage` にカテゴリ別クリア数・獲得シール・連続日数を保存（DB不要）。
- コレクション帳＝獲得シール一覧。集める動機づけが継続率の核。
- 保護者エリアで簡易サマリ表示。

## 11. 開発・納品フロー（すりあわせ → 段階拡張）

「できあがりイメージのすりあわせ」を最優先し、**少数問題のプロトタイプで見た目・操作感を合意してから問題数を増やす**進め方とする。

| フェーズ | 内容 | 問題数 | 外部依存 | ゴール |
|---|---|---|---|---|
| **P0 すりあわせ用プロトタイプ** ← 今ここ | 親ログイン（モック）→子画面切替、色・形を各3問、ノーフェイル・読み上げ・ごほうび演出。単一HTML（`prototype.html`） | 各3問 | なし | 見た目・操作感・トーンの合意 |
| **P1 MVP実装** | プロトタイプをNext.js化。Auth.js＋Google＋許可リストで**本番ログイン**に差し替え。色・形を本実装＋Vercelデプロイ | 各5〜10問 | Google OAuth | 本番ログインで子画面が動く |
| **P2 音声** | ElevenLabs音声パイプライン構築、P1へ読み上げMP3を適用 | 同上 | ElevenLabs | 全問読み上げ |
| **P3 画像種目** | かず＋なかまあつめ（物体イラスト生成）、ごほうび/コレクション | 拡張 | Higgsfield/Nano Banana Pro | 画像系種目の追加 |
| **P4 拡張** | おとさがし・ひらがなタッチ・えあわせ、保護者エリア拡充、問題数を大量化 | 大量 | 追加画像/音声 | 教材として運用可能 |

> **判断ゲート**：P0でOKが出たらP1へ。NGなら配色・マスコット・操作感・文言をP0で調整してから先へ進む（手戻りを最小化）。

## 12. セットアップ / 環境変数（キーは後設定）

```
# 認証（Auth.js + Google）
AUTH_SECRET=（openssl rand -base64 32 で生成）
GOOGLE_CLIENT_ID=（Google Cloud Console で取得・あとで設定）
GOOGLE_CLIENT_SECRET=（同上・あとで設定）
ALLOWED_EMAILS=parent1@gmail.com,parent2@gmail.com   # 許可リスト（DB不使用）

# 音声生成（生成スクリプト用。本番ランタイムには不要）
ELEVENLABS_API_KEY=（あとで設定）

# 画像生成（Higgsfield/Nano Banana Pro）はビルド/オフライン工程で使用。本番アプリはキー不要。
```

- Google OAuth: Google Cloud Console で OAuth クライアント作成、リダイレクトURIに `https://<本番>/api/auth/callback/google` と `http://localhost:3000/api/auth/callback/google` を登録。
- Vercel：通常デプロイ。`public/`はCDN配信。アドレス追加は `ALLOWED_EMAILS` に追記して再デプロイ。
- 実行時のサーバーレス関数はファイルシステムが**読み取り専用**＝実行時に画像/音声を書き出す設計にしない（すべて事前生成）。

## 付録A：P0プロトタイプ（`prototype.html`）の仕様
- 単一HTML（外部依存はGoogle Fontsのみ）。タブレットのブラウザで直接開ける。
- 保護者ログインは**モック**（ボタン押下→「ログイン中…→許可リスト確認→ようこそ」を演出して子画面へ）。本番はAuth.js＋Googleに差し替え。
- 色3問・形3問。タップで回答、正解でキラキラ＋星獲得＋マスコットが喜ぶ、間違いは「もういちど」（ノーフェイル）。
- 読み上げは暫定で端末のWeb Speech（`speechSynthesis`, ja-JP）。本番はElevenLabsのMP3に置換。
- マスコットタップで読み上げ再生。右上ロックの長押しで保護者メニュー（ログアウト相当）。
